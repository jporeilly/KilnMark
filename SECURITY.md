# Security policy

## Supported versions

Kilnmark is before 1.0. Security fixes go into the next release; there are no fixes to earlier
releases. Upgrade to the latest release to get them.

## Reporting a vulnerability

Please report a vulnerability privately, never in a public issue, discussion or pull request.

**Contact:** OWNER TO SET BEFORE THE FIRST RELEASE (a monitored address for security reports).

Include what you can of:

- the Kilnmark version (the release file or folder name, `kilnmark-<version>`);
- what an attacker can do, and what they need first (a role, a network position, a setting);
- steps or a request that shows it, with any data synthetic;
- whether it is known to anyone else.

## What happens next

- We acknowledge a report within three working days, and say within ten whether we accept it.
- We fix accepted reports in order of severity. A fix ships in a release whose changelog says
  what was fixed, once customers can upgrade, and credits you unless you ask us not to.
- We agree a disclosure date with you; ninety days from the report unless we agree otherwise.

## Checking what you received

Every release is signed, and carries SBOMs of what it contains. INSTALL.md, "Check a release",
says how to verify one.
